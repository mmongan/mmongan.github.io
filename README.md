# OpenChartxr: WebXR Marching Band Drill Designer

A browser-based marching band drill designer built with Babylon.js. Create and edit robot formations and paths on a football field, then preview synchronized movement in a 3D stadium. The scene supports desktop browsers and immersive VR or AR on compatible headsets such as Meta Quest 3.

## Run locally with Vite

From this project folder, install dependencies and start the dev server:

```bash
npm install
npm run dev
```

Then open:

- http://localhost:5173 on your development machine
- http://<your-computer-ip>:5173 from the Meta Quest browser

For headset testing, open the local address in an XR-capable browser. WebXR features require a secure context: localhost is suitable for local development, while access from another device generally requires HTTPS. The deployed GitHub Pages site is served over HTTPS.

## Deploy to GitHub Pages

```bash
npm run deploy
```

Builds the project, copies `dist/` into the repository root, then commits and pushes the generated `index.html` and `assets/` to `origin main`. The command refuses to run unless the current branch is `main`. It makes a Git commit and pushes automatically, so use it when you intend to publish.

## OpenMarch .dots format compatibility

OpenChartxr reads **OpenMarch `.dots` show files**, which are SQLite databases, not plain-text dot lists. This is drill-data compatibility, not a complete replacement for the OpenMarch editor.

### Open a show

1. In Settings, paste a downloadable `.dots` URL into **Open OpenMarch show (.dots URL)** and press **Open**.
2. Alternatively, share a startup link: `https://mmongan.github.io/?openmarch=https%3A%2F%2Fexample.com%2Fshow.dots`.
3. Use **Load example OpenMarch show**, or `?openmarch=example`, to restore the bundled example.

GitHub file-page links and Dropbox share links are converted to download URLs. Other servers must permit cross-origin downloads (CORS). Only HTTP/HTTPS URLs are accepted; there is currently no local `.dots` file picker. Opening a show replaces the current marchers and drill. Download/format failures are reported in Settings.

### Supported data and limitations

| OpenMarch data | OpenChartxr behavior |
| --- | --- |
| Marchers and page dots | Reads `marchers`, `pages`, `beats`, and `marcher_pages`; converts field coordinates into one position per marching count. Marchers without dots are omitted. |
| Midsets | Includes midset positions as intermediate keyframes; movement is linearly interpolated through them. |
| Page timing and subsets | Uses beat positions and final-page count settings. Preserves page/subset labels such as `2A`, page-number offsets, and page notes in the show display. |
| Marcher information | Displays drill label, name, section, and assigned instrument. Section names are matched to the closest available instrument; unknown sections retain the currently selected instrument. |
| Field coordinates | Uses field-property data when available, converting OpenMarch's 18-pixels-per-yard coordinates to the stadium field. Custom field images and artwork are not reproduced. |
| Tempo | Derives one tempo from the median positive beat duration, clamped to 60–120 BPM. Authored tempo changes are not reproduced. |
| Curved pathways and facing | Curved pathway geometry and authored facing rotations are not imported; playback follows straight segments through dots/midsets and derives marcher facing from movement. |
| Audio and visual metadata | Embedded show audio, equipment/appearance overrides, shapes, tags, and editor history are not imported into the scene. Load MIDI separately for synchronized music. |

The reader checks the required tables rather than promising compatibility with every past or future OpenMarch release. The database writer used by the bundled-example generator targets the OpenMarch schema through migration `0016` (`user_version = 7`), but **there is currently no user-facing `.dots` export or lossless round-trip editing workflow**. Preserve your original show and use OpenMarch for full-fidelity editing.

Implementation: [OpenMarch database conversion](src/robot/openMarchFormat.ts), [URL loading](src/robot/openMarchUrl.ts), and [example generator](scripts/make-openmarch-example.mts). Format compatibility does not imply affiliation with OpenMarch.

## Features

- Settings -> **Drill form editor** exposes line, arc, circle, block, polygon, and star tools for standing formations. Choose an empty origin and target spacing to add forms without replacing an imported show. Select a form in the list or select one of its marchers, then translate, rotate, scale, or adjust spacing for the whole form. Spacing changes scale the form while preserving its marcher count, identities, and instruments; original curve sampling may round intervals to fit endpoints.
- Optional field-grid snap uses 0.3125, 0.625, 1.25, 2.5, or 5-yard intervals; angle snap uses 45 degrees. Settings and the XR palm form library share snap/spacing settings. The palm library also provides spacing, rotation, and scale buttons; existing controller/hand handles still move and reshape forms. Group edits validate all marchers together and roll back on collisions. Imported marching routes are intentionally excluded from these standing-form controls. Run `node scripts/check-drill-editing.mjs` for focused checks.
- Each block row is a separate selectable form. Group controls edit one standing form at a time, not arbitrary multi-selection. These tools do not add form saving/export or transform undo/redo; successful edits clear existing erase history.
- OpenMarch-style alignment tools in the same editor align X or Z to the form's average coordinate, distribute marchers evenly between the existing axis extremes, or round positions to whole yards (keyboard `1` outside text fields). Marcher order, identity, height, facing, and instruments are preserved; collisions reject the entire operation, and imported/attached routes remain protected. Alignment replaces the form's guide with a connected guide through the edited marcher positions rather than fitting it back to a circle.
- Grid presets populate independently editable X/Z rounding intervals (0.001–10 yards). Hold `Shift` to bypass grid and angle snapping temporarily; releasing Shift or leaving the window restores the configured settings. X/Z translation locks apply to the form transform and standing-form controller move/control-point handles, including when snapping is enabled. They do not constrain rotation, scaling, alignment, individual marcher grabs, or marching-route edits.

- Palm-menu instrument buttons display miniature 3D instrument models instead of abbreviations. Their existing click/trigger/pinch targets and active-instrument highlight are preserved.
- Manual marcher placement, controller/hand dragging, fingertip pushing, and standing-formation edits reject body or instrument overlaps. Dragging a count handle also checks the other marchers at that count. Collision checks use the models' oriented part bounds, including protruding horns and percussion, and swept movement catches jumps between input frames. Blocked moves retain the last valid pose; invalid new placements stay hidden. A browser notice explains rejected edits. Imported/authored drill paths and playback remain unchanged, including any existing collisions; collision avoidance does not move marchers off their written routes. Run `node scripts/check-manual-placement.mjs` for the focused checks.

- The startup video board displays the application version from `package.json`, alongside the build timestamp.
- Stadium environment with turf, field markings, stands, goal posts, scoreboard, and a video board
- Main-field yard lines, sidelines, and end lines are 4 inches wide; hash marks are 4 inches by 24 inches. NFL goal lines are 8 inches wide. Turf-strip boundaries share one centered line instead of doubling its width; video-board markings remain enlarged for readability.
- Animated thighs span the fixed hip and moving knee, keeping the upper legs attached during fast and high-step gaits without changing foot placement. Check joint attachment with `node scripts/check-thigh-attachment.mjs`.
- The straight jacket hem ends at hip level, exposing the full thighs, knees, and lower legs, without a separate buttock or pelvis mesh. Check geometry with `node scripts/check-marcher-seat.mjs`.
- Thigh and calf joint lengths are balanced at 0.315 model units each; a shared rounded knee joint covers the bending seam. Shoes are approximately 27.6 cm long, 8-9 cm wide, and 7.9 cm high at adult scale. Shoe centers sit ahead of the ankle pivot so the lower leg connects near the heel, and the foot-contact solver uses the same offset. The slimmer shoes and balanced leg lengths preserve standing height.
- Feet keep the torso's facing throughout marching, including crab/sideways travel and turns. Only heel/toe pitch changes independently for ground contact; feet do not yaw toward the travel direction while the body faces elsewhere.
- Swing feet use a continuous eased lift arc with zero vertical speed at lift-off and landing, rather than interpolating nine lift samples. Peak lift is limited before shaping the arc so knee-reach clipping does not flatten the top of ordinary steps. Field-march clearance peaks around 17 cm at adult scale; supporting feet remain planted and swing feet still land on the MIDI pulse.
- Field marchers share 10 instanced body-part sources and two materials, including the rounded knee joint. All body parts switch to cached low-detail geometry together; held/preview rendering groups use shared-geometry clones. Jacket clipping batches the four leg planes with one body-matrix inversion per marcher, reusing cached world transforms instead of forcing hierarchy updates for each limb.
- Leg surfaces above the jacket hem are clipped in body coordinates, preventing animated thighs and calves from showing through the coat at either detail level, including instanced marchers and held/preview clones. The boundary follows body rotation and AR scaling.
- The jacket has a straight, closed, level hem with no exposed band or rounded bottom bulge; its underside meets the leg clipping boundary.
- Knee flexion is capped at 1.35 radians (about 77 degrees) without backward hyperextension. Foot-target IK uses fixed thigh and calf lengths; the legs have a uniformly scaled rig so the narrow jacket build does not shorten their reach. Field-march supporting knees stay straight: toe/heel roll supplies ground contact instead of crouching. Only the lifted swing leg bends. The torso stays at its upright standing height instead of bouncing with each footfall, and swing lift is limited by knee reach. Desktop/VR POV follows a stable root-relative eye height, not leg animation. Check joint attachment with `node scripts/check-thigh-attachment.mjs` and fixed lengths, straight stance knees, stable torso height, sole contact, and extreme-route limits with `node scripts/check-midi-footfall-position.mjs`.
- Footfalls follow the MIDI's metrical pulse: simple meters use the denominator note, while compound meters such as 6/8 use groups of three eighth notes (dotted-quarter pulses). The bundled Liberty Bell therefore marches at 120 main pulses per minute from its 180-quarter-note BPM map. Auto half-/double-time are relative to that pulse, and meter changes preserve cumulative pulse position.
- Feasible moves keep planted feet fixed on the field while the other foot swings to its next landing. Automatic half-/double-time uses distance per MIDI pulse, not per quarter note, and targets at most an 8-to-5 stride (0.625 yard). When even double time or a sharp turn exceeds leg reach, the preview bounds foot movement and displays an "Unmarchable move" notice instead of stretching the legs. Authored route positions and MIDI timing remain unchanged; these flagged, physically impossible moves can slide.
- Marchers use a soft, clay-like body silhouette: rounded jacket shoulders and hem, gently filled-out limbs, overlapping rounded joint ends, and softer highlights. Uniform colors, faces, hats, instrument grips, joint centers, and beat-driven animation are preserved. Both detail levels share cached body-part meshes; `node scripts/check-marcher-seat.mjs` validates the body geometry.
- Marchers are adult-sized: 1.8 meters (about 5 feet 11 inches) from soles to skull crown, excluding the shako and plume. Standard 8-to-5 travel is 0.625 yard (22.5 inches) per step; leg animation converts field-yard travel into scaled body coordinates. Imported drills retain their authored positions and variable step sizes. Check height and stride conversion with `node scripts/check-marcher-scale.mjs`.
- In VR/AR, tracked-hand pinches can operate chart buttons or grab the pad using the hand's pointing ray as well as direct near contact. Buttons take priority over grabbing. Controller triggers and grips also use standard WebXR gamepad buttons when a motion-controller profile is unavailable.
- MIDI also loads from Settings → MIDI URL or a shared `?midi=<encoded-http-or-https-url>` link. Servers must allow CORS downloads; failures are shown without replacing previously loaded music. Startup loads **The Liberty Bell**, J. P. Sousa (1893), as a full-band MIDI with 20 nonempty tracks: piccolo, flute, oboes, clarinets, bassoons, saxophones, horns, cornets, baritone, trombones, tuba, and two percussion tracks. The [Internet Archive source](https://archive.org/details/InternetJukebox.JPS.48) marks this item with the [Public Domain Mark](https://creativecommons.org/publicdomain/mark/1.0/); its [original full-score MIDI](https://archive.org/download/InternetJukebox.JPS.48/99%20Liberty%20Bell%20-%20Full%20Score.mid) is bundled unchanged with the app. **Load Liberty Bell full-band score** restores it. The score defaults to **Full score (20 parts)**, and individual parts remain selectable. This replaces the previous piano reduction; it is not a piano track remapped to band instruments. MIDI audio is enabled by default, but browser permissions require a first click, tap, or keypress to unlock sound. Loading MIDI applies its original tempo map to the shared drill/music clock; manually changing march tempo overrides that map. The bundled drill and music are not a historically matched show.
- Import local `.mid` / `.midi` music under Settings → Drill music. The first click, tap, or keypress automatically unlocks default-enabled MIDI audio; interact with the page before entering VR/AR. Settings → Mute MIDI audio stays muted across further interactions until Enable MIDI audio is clicked. Browser-suspended audio resumes on another interaction unless explicitly muted; failures display an Enable MIDI audio retry instruction. MIDI files stay in your browser; nothing is uploaded. One drill count equals one quarter-note beat starting at count 0; the loaded MIDI tempo map drives playback unless manually overridden. Footfalls read the exact current MIDI beat position at the auto-selected normal, half-, or double-time cadence. Pausing freezes the current pose and fractional beat; seeking and song loops align feet to the selected music position, while a drill-only loop does not restart the continuous music phase. All drill controls (including chart-page seeks and media jogging) drive the same audio transport. Pause/seek cancels queued notes, playback resumes held notes at the selected beat, fast-forward speeds the music up, and rewind is muted. Music stops at the drill's end; longer files are truncated and shorter files finish naturally. Volume, mute, and Clear MIDI are available in Settings. The [smplr JavaScript sampler](https://github.com/danigb/smplr) plays FluidR3 General MIDI instrument samples and channel-10 percussion from [Paul Rosen's soundfont hosting](https://paulrosen.github.io/midi-js-soundfonts/). Unlocking audio downloads the required instruments and decodes only the pitches used by the file; sample loading needs internet access and failures are reported with a retry option. Sustain/controllers and pitch bends are not interpreted. Formats 0/1 with quarter-note timing are supported (not SMPTE or format 2), up to 10 MB / 100,000 notes and 64 simultaneous voices; voice-limit omissions are reported. Imports last for the current session and must be reloaded after refreshing. Check synchronization with `node scripts/check-midi-sync.mjs`, footfall phase with `node scripts/check-midi-footfall-position.mjs`, default audio activation with `node scripts/check-midi-activation.mjs`, and sampler dispatch with `node scripts/check-sampled-midi.mjs`.

- Settings -> **Sheet music (MIDI preview)** renders loaded MIDI with [VexFlow](https://vexflow.com/). Multiple tracks default to **Full score**, with bracketed systems, track labels, and synchronized beat alignment, or select individual tracks. Choose **Measures per page** (`Auto`, 1, 2, 3, 4, or 8) and **Follow drill playback** to follow music with a highlighted measure. The room-scale music stand is hidden by default; **Show music stand with score** opens it on your right, and **Place music stand to my right** explicitly repositions it. It stays world-fixed after release and independent of tabletop scaling. Mouse drag moves it, the wheel changes distance, and controllers/hand pinches grab it directly or remotely. Hiding cancels grabs. Track selection and page browsing remain in Settings. Rendering loads only when the stand or preview is visible and needs no audio permission. Notes are quantized to sixteenths in fixed 4/4 measures with clefs, accidentals, rests, chords, and ties; original meter, enharmonic spelling, voices, and expression are not reconstructed. Percussion uses MIDI pitches rather than conventional drum notation. Import/URL/example changes refresh the score; failed imports retain it and Clear MIDI removes it. Checks: `node scripts/check-midi-notation.mjs` and `node scripts/check-floating-panels.mjs`.

- The floating music stand has interactive media controls (**rewind**, **previous count**, **play/pause**, **next count**, and **fast-forward**) along the bottom, plus **Staff: [Auto|8|4|3|2|1]** and **Hide** controls on the top bar. Grab the music pad with both controllers (grip or trigger on the pad) or pinch it with both tracked hands, then spread apart to enlarge or bring together to shrink it between 60% and 250%. One hand moves the pad; releasing either hand after stretching continues a one-handed grab without a jump. Releasing both leaves its size and placement unchanged. Hiding or explicitly placing it cancels both grabs. Desktop users can still use Settings → **Music pad size**. Measures are packed into a grid chosen to maximize their rendered size and fill the pad, rather than stacking tall full-band systems into a narrow column. In `Auto` staff mode, the 20-part score shows three measures across at 100% pad size and five at 150%; smaller ensembles retain their existing automatic measure counts. Clicking **Staff: N** cycles through layout densities, including an eight-measure overview and a one-measure large-print option. Settings → **Measures per page** offers the same overrides. Click on desktop, use controller triggers, or pinch near a button or aim/pinch with a tracked hand. These use the same drill transport as the chart and video board; step buttons pause on the adjacent count, fast-forward runs at double speed, and rewind runs backward with MIDI muted. Buttons take priority over grabbing the score, and Play/Pause reflects the shared playback state. An orange beat marker advances once per quarter-note drill count in both the stand and Settings score, including over held notes and rests. Only the current measure's cell is highlighted. The stand also shows the current count and beat within its 4/4 measure. Seeking, stepping, speed changes, pause, and reverse use the same transport clock; no separate music timer is used.

- Marchers are robots with a low-poly humanoid android head in the same smooth-shaded style as the body: a pale rounded skull with a flat face, a navy visor band with glowing cyan eyes, a mouth slit, and disc ears, under the shako and plume.

Existing marchers swap geometry in place when the scale changes, and new marchers and instrument changes use the current level.
- Instruments use smoother circular cross-sections at full scale: 12–24 sides for tubing, 32–48 for bell rims and larger drum shells, with matching tessellation for caps and bell transitions. The sousaphone body loop has 32 segments at full scale and 16 when shrunk. Instrument sizes, mouthpiece and grip positions, colors, and playing/carry poses are preserved. This adds geometry but no extra meshes or materials; hardware instances and held-marcher clones still share their template geometry. Validate both detail levels with `node scripts/check-instrument-geometry.mjs`.
- Instrument tubing bends are rounded with quadratic fillets rather than sharp corners. A 90-degree bend has eight curved segments at full scale and four when shrunk; tighter turns get more segments. Fillets stay within 30% of the shorter neighboring segment, preserve open tube endpoints, interpolate bore radii, and leave straight sections and marcher bodies unchanged.
- Instrument tubes are seam-free: bends are mitered so they never pinch, each bell flares straight on from its pipe as one tube, mouthpieces sit inside straight receivers, tube ends finish inside valve blocks and braces, and the sousaphone's body loop is closed. Marcher joints are seamless too: shoulders, elbows, hips, and knees bend around rounded caps, and the forearm stretches slightly when a grip is just out of reach, so wrists stay attached to the hands.
- Marchers hold their instrument with both glove hands in playing and carry poses, with articulated elbows connecting their sleeves to the instrument's grip points.
- Trumpets are a procedural B♭ horn sized for Meta Quest: mouthpiece, leadpipe and tuning slide, valve block with three pearl buttons, bell bow, and flared bell at true proportions. Every horn is an instance of one shared, hand-indexed 883-vertex mesh with a single vertex-colored material, so all trumpets share one draw call. The left hand wraps the valve casings and the right hand rests on the buttons.
- Mellophones use the same style and right-handed valve layout as the trumpet, with a longer leadpipe, a deeper tuning-slide wrap, and a much larger forward bell, as one shared 811-vertex mesh. They are held like a trumpet when played and carried upright with the bell down.
- Alto saxophones use the same style: a conical body, bow and upturned bell in one rounded tube, a curved neck, a black mouthpiece, and pearl key stacks, as one shared 897-vertex mesh. The left hand sits on the upper key stack and the right hand on the lower; when played, the horn hangs down and slightly out to the marcher's right.
- Baritone saxophones are about one and a half times the alto's size, with a wider bore and bell and an open S-curved neck above the body, not a spiral (1,617 vertices). They are held further out to the marcher's right.
- Euphoniums are carried like the mellophone with a large front-facing bell, wrapped leadpipe, valve block, and three pearl valve buttons (1,099 vertices).
- Trombones use the same style: mouthpiece, a widened forward slide with its crook and brass crosspiece, and a bell section whose tuning slide passes over the marcher's left shoulder. The return rail lines up with the bell section and runs straight into it without sideways neck bends, so the whole horn is one continuous tube, as one shared 692-vertex mesh. The left hand rests beside the receiver and the right hand holds the brass crosspiece at first position. There is no crosspiece attached to the mouthpiece, and both gloves stay clear of the main tubes. In the carry pose the trombone is held upright with the slide pointing down.
- Clarinets use the same style: a black mouthpiece with a silver ligature, barrel, straight body with silver front key clusters, and a flared bell, as one shared 289-vertex mesh. They are played angled about 40° below horizontal, with the left hand on the upper joint and the right hand on the lower joint, and carried upright in front of the chest.
- Flutes use the same style: a silver head joint and body with a lip plate, a dark embouchure hole, and front key rows, as one shared 129-vertex mesh. They are played level out to the marcher's right, with the lip plate under the mouth grille, the foot angled slightly forward, and the left hand crossing in front of the chin with its elbow swung out to the side, clear of the chest. They are carried upright with the crown up.
- Sousaphones are worn rather than held, as one shared 2,164-vertex brass mesh: a tilted body loop rests on the left shoulder and passes under the right arm, a gooseneck reaches the mouth, and the bell faces forward above the shako. The right hand sits on the valves and the left hand on the front of the loop; playing and carrying use the same pose.
- Percussion is worn on a carrier in the same style, with the sticks or mallets in the marcher's hands: a silver snare drum with pearl heads (250 vertices), navy quad tenors with felt-tipped mallets (460 vertices), and a navy bass drum turned on its side with a felt mallet beside each head (266 vertices), and a glockenspiel with graduated silver bars, its sharps on a raised rail, and red-tipped mallets (160 vertices).
- Choose an instrument (Trumpet, Mellophone, Trombone, Euphonium, Sousaphone, Alto saxophone, Baritone saxophone, Clarinet, Flute, Snare drum, Tenor drums, Bass drum, or Glockenspiel) in Settings → Robot paths, or on the palm-up hand menu with the brass row (`Tpt`/`Mel`/`Tbn`/`Eup`/`Sou`), woodwind row (`Alto`/`Bari`/`Cl`/`Fl`), and percussion row (`Sn`/`Ten`/`BD`/`Glk`). The pick changes the selected marcher's instrument and is used for every marcher created afterwards. The active choice is highlighted on the hand menu.
- Automatic gait: when the scoreboard gait selector shows `AUTO` (Field March, High Step, Parade, or Knee-Ankle March style), each marcher's gait is worked out count by count from its facing, travel direction, and step size. A stationary count is mark time (high mark time for High Step/Knee-Ankle). Travel within 50° of facing marches forward in the selected style, beyond 130° is a backward march (backward high step for high-lift styles), and in between is a crab walk with legs along the line of travel. Steps shorter than 0.36 yd per count (for example 16-to-5) march half time, and steps longer than 1.05 yd (for example 4-to-5) double time, so the stride stays near 8-to-5. Marchers whose route has ended halt at attention. Selecting any other gait (Crab Walk, Slide, Mark Time, Double Time, Backward March, and so on) forces it on every marcher as before. With tracked hands, twist a scheduled marcher at least 20° while holding it to make it keep that facing for its whole route, so forward moves become slides or back-marches; twist it back toward its path to face the direction of travel again.
- Shared count-based playback with play/pause, rewind, fast-forward, single-count stepping, and timeline seeking; playback controls are available on the video board and the palm-up VR controller or tracked-hand menu. The hand menu's Form page offers Line, Arc, Circle, Block, Triangle, Square, Pentagon, Hexagon, and Star formations, plus A-Z letter formations, around the held or selected marcher.
- Collision-marker previews and controls for showing paths and testing larger robot groups
- Immersive VR with teleport locomotion and immersive AR with the stadium scaled to a tabletop
- In VR floor/Giant mode, teleport using controllers only. Hand gestures never teleport. Controller teleport is disabled during floor calibration, in tabletop mode or AR, and whenever the field is smaller than 2 meters along its longest side. It preserves field scale, and its target scales with the field.
- Settings → Controller roles assigns left-hand navigation (teleport and turning) and right-hand media jogging by default. Enable Right-hand navigation / left-hand media jogging to swap them, including during an XR session. Only the media controller's thumbstick jogs the timeline left/right while the palm-up menu is open; the navigation controller cannot jog playback. The setting also selects the jogging hand in AR, where teleportation remains disabled.
- Enable Hand-tracked thumb media jogging in the same settings group for a virtual thumbstick on the assigned media hand. With the palm-up menu open, curl the fingers and extend the thumb; hold it steady for 0.3 seconds to establish neutral, then move it sideways relative to the palm to jog. The existing deadzone and proportional jog speed apply. Opening the hand, lowering the thumb, pinching, losing tracking, closing the menu, or starting floor calibration stops the gesture. Controller input takes priority when a media controller is connected. This gesture never navigates or teleports.
- In VR or AR, use both controllers to move, rotate, and scale the stadium between tabletop and full size. Shrinking with controllers or tracked hands across the default tabletop size (a 1-meter-long field) raises the field to the configured Table height; continued resizing preserves that height unless you move your hands vertically.
- Giant mode fits the field uniformly inside the configured room width and length (1-50 meters each; defaults to 4 by 5 meters). Use the Giant mode button in settings; changing room dimensions while active updates the fit. In XR, the field surface follows the headset's local-floor reference rather than the Floor height slider, with physical eye height and rotation preserved. Tabletop/full-scale buttons and explicit floor calibration exit Giant mode. Dimensions describe the field footprint, not the surrounding stadium or a detected safety boundary.
- Tracked hands use Babylon.js skeleton-skinned hand meshes, mapped to WebXR joint bones and rendered with an off-white marching-band glove material in VR and AR.
- In VR or AR, pinch with both tracked hands outside the field to translate, rotate, and zoom the scene: move the midpoint to translate, turn the hands to rotate, and change their separation to scale. Both pinch points must remain outside the field. Zooming scales around the hands horizontally while keeping the field surface at its current height, except when shrinking across the tabletop-size threshold applies the configured Table height. Release either pinch to stop; two-hand manipulation does not start while a hand is holding a marcher.
- In VR or AR at any scale, pinch near a marcher with one hand to grab it, move your hand, and release to place it on the field. Turn your hand while pinching to rotate the marcher to face any direction. Pinching empty space above the stadium ground creates a marcher in your hand; move it onto the field and release to place it. Empty-space pinches outside the stadium ground do not create marchers. While holding a marcher, pinch it with your other hand and pull away: marchers appear in the air along the pulling hand's traced curve, constrained to a horizontal plane parallel to the field. Pull straight for a line, trace an arc for a curved formation, or trace a circle back to the starting marcher to close the loop without duplicating the first marcher. While shaping, move the pulling pinch onto a preview marcher and push or pull it to bend that part of the chain; nearby marchers follow smoothly. Release the pulling hand to finish shaping, then move and rotate the formation with the anchor hand. Releasing the anchor leaves the formation floating: pinch any of its marchers to pick up and reposition the whole formation, as often as needed. Turn a hand palm-up and pinch near its Commit button to place the formation on the field; controller triggers can also activate Commit. The button appears only after shaping is finished. Releasing the anchor before finishing shaping cancels the formation. Losing tracking while holding the formation cancels it; a released floating formation persists until committed or the XR hand-tracking session resets.
- In tabletop mode, grip a marcher with a controller, then turn the controller while holding it to rotate the marcher; release the grip to place it.
- Grabbed marchers and airborne formation previews render in front of tracked hands and controller models so they stay visible. Released or canceled marchers return to normal depth rendering.
- Uncommitted formations have a cyan outer glow while shaping, floating, or being repositioned. Committing or canceling removes the glow.
- Touch an on-field marcher with an unpinched index fingertip and push to slide only that marcher, keeping its feet on the field and its facing unchanged. Both hands can push different marchers in different directions simultaneously. Moving the finger away stops the push; pinching switches to normal grabbing. This does not draw a marching path or move the rest of a formation.
- Enable Erase marchers in settings or toggle the orange-highlighted Erase button in the palm-up menu. Click a marcher on desktop, aim and press a controller trigger, pinch near a marcher, or touch it with an unpinched index fingertip to delete only that marcher. Move the fingertip at least 4 cm before another touch deletion. Erase disables placement, grabbing, finger pushing, and two-hand scene manipulation, and pauses during floor calibration. Enabling it finishes pending formation placement so individual members can be erased. Deleted members stay missing when their formation is reshaped.
- Eraser deletions have a session-local undo/redo stack of up to 100 actions. Use Undo erase/Redo erase in settings, Undo/Redo in the palm-up menu, Ctrl/Cmd+Z to undo, or Ctrl/Cmd+Shift+Z (also Ctrl/Cmd+Y) to redo. Text inputs keep their native shortcuts. Undo restores the same marcher, formation membership, path, and count schedule; redo deletes it again. New erasures discard redo history. Reshaping/rebuilding a formation or path, and generating a replacement drill, clear deletion history; other editing actions are not undoable.
- The drill chart starts hidden. Toggle it with **Chart** in the palm menu or **Drill chart pad** in Settings; the corner **X** closes it. It opens ahead and to your left, opposite the score, at room scale. Each page is an 8-count set (plus the final count), with yard lines, hashes, marcher dots, previous-set dots, and dashed movement lines. Pinch, controller grip/trigger, or mouse-drag to move it; releasing leaves its world pose unchanged. Mouse wheel adjusts distance. A manually placed chart retains its position across hide/show unless you are more than 2.5 m away, in which case reopening places it nearby. Prev/Next seeks the corresponding set; playback changes pages automatically. Check with `node scripts/check-panel-placement.mjs`.
- Two-hand hand-tracked formations are created in a horizontal plane parallel to the field. Trace an open curve for a smoothly spaced arc, or close the loop to fit a true horizontal circle through the held marcher. Pulling a marcher on a closed loop stretches or compresses the circle into an ellipse while keeping the anchor marcher fixed. Pulling the free end of an open arc outward progressively straightens the chain; dragging a marcher in the middle reshapes it locally.
- To resize an existing circle with tracked hands, pinch two different marchers on that circle and move your hands apart or together. The circle stays centered and circular, with marchers respaced as its radius changes. Release either pinch to keep the new size; losing hand tracking or enabling floor calibration cancels the resize.
- Floor calibration only runs when explicitly enabled using the Floor calibration checkbox; entering XR, teleporting, and touching the floor do not start it automatically
- Separate Floor height (-2 to 2 m) and Table height (0 to 2 m) sliders set the field surface height. Full-scale applies the floor setting; Giant mode uses the tracked local floor in XR; tabletop mode applies the table setting. Values are remembered during the session, defaulting to 0 m and 1 m respectively; adjusting a height does not start calibration.
- At 1:1 VR scale, the horizon ground follows the field's position while remaining below the turf. It stays world-sized and is hidden at reduced scales and in AR.
- Sitting mode selects a tabletop up to 0.75 m above the local floor; Standing selects up to 1 m. In XR, automatic placement lowers it as needed to stay 0.45 m below measured eye level, stopping at the floor. The tabletop slider remains adjustable afterward. Full-scale VR keeps your physical eye height when standing, so your real floor stays level with the turf (including any saved floor calibration), and uses a 1.2 m virtual eye height in Sitting mode; Giant and tabletop modes preserve physical eye height. AR headset tracking is unchanged.
- In VR and AR, physical headset height automatically selects sitting or standing table height after one second of stable detection. Initial detection uses 1.425 m; subsequent transitions use below 1.35 m for sitting and at least 1.5 m for standing. Tabletop entry also adjusts height immediately when a tracked pose is available. Automatic detection does not change virtual eye height, is paused during floor calibration, and leaves manual table-height adjustments intact until the next detected posture change.
