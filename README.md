# OpenChartxr: WebXR Marching Band Drill Designer

A browser-based marching band drill designer built with Babylon.js. Create and edit robot formations and paths on a football field, then preview synchronized movement in a 3D stadium. The scene supports desktop browsers and immersive VR or AR on compatible headsets such as Meta Quest 3.

## Run locally with Vite

From this project folder, install dependencies and start the dev server:

```bash
npm install
npm run dev
```

Then open:

- http://localhost:5173 on your development machine
- http://<your-computer-ip>:5173 from the Meta Quest browser

For headset testing, open the local address in an XR-capable browser. WebXR features require a secure context: localhost is suitable for local development, while access from another device generally requires HTTPS. The deployed GitHub Pages site is served over HTTPS.

## OpenMarch .dots format compatibility

OpenChartxr reads **OpenMarch `.dots` show files**, which are SQLite databases, not plain-text dot lists. This is drill-data compatibility, not a complete replacement for the OpenMarch editor.

### Open a show

1. In Settings, paste a downloadable `.dots` URL into **Open OpenMarch show (.dots URL)** and press **Open**.
2. Alternatively, share a startup link: `https://mmongan.github.io/?openmarch=https%3A%2F%2Fexample.com%2Fshow.dots`.
3. Use **Load example OpenMarch show**, or `?openmarch=example`, to restore the bundled example.

GitHub file-page links and Dropbox share links are converted to download URLs. Other servers must permit cross-origin downloads (CORS). Only HTTP/HTTPS URLs are accepted; there is currently no local `.dots` file picker. Opening a show replaces the current marchers and drill. Download/format failures are reported in Settings.

### Supported data and limitations

| OpenMarch data | OpenChartxr behavior |
| --- | --- |
| Marchers and page dots | Reads `marchers`, `pages`, `beats`, and `marcher_pages`; converts field coordinates into one position per marching count. Marchers without dots are omitted. |
| Midsets | Includes midset positions as intermediate keyframes; movement is linearly interpolated through them. |
| Page timing and subsets | Uses beat positions and final-page count settings. Preserves page/subset labels such as `2A`, page-number offsets, and page notes in the show display. |
| Marcher information | Displays drill label, name, section, and assigned instrument. Section names are matched to the closest available instrument; unknown sections retain the currently selected instrument. |
| Field coordinates | Uses field-property data when available, converting OpenMarch's 18-pixels-per-yard coordinates to the stadium field. Custom field images and artwork are not reproduced. |
| Tempo | Derives one tempo from the median positive beat duration, clamped to 60–120 BPM. Authored tempo changes are not reproduced. |
| Curved pathways and facing | Curved pathway geometry and authored facing rotations are not imported; playback follows straight segments through dots/midsets and derives marcher facing from movement. |
| Audio and visual metadata | Embedded show audio, equipment/appearance overrides, shapes, tags, and editor history are not imported into the scene. Load MIDI separately for synchronized music. |

The reader checks the required tables rather than promising compatibility with every past or future OpenMarch release. The database writer used by the bundled-example generator targets the OpenMarch schema through migration `0016` (`user_version = 7`), but **there is currently no user-facing `.dots` export or lossless round-trip editing workflow**. Preserve your original show and use OpenMarch for full-fidelity editing.

Implementation: [OpenMarch database conversion](src/robot/openMarchFormat.ts), [URL loading](src/robot/openMarchUrl.ts), and [example generator](scripts/make-openmarch-example.mts). Format compatibility does not imply affiliation with OpenMarch.

## Edit a standing formation

1. Open **Settings -> Drill form editor**.
2. Choose a form tool, an empty field origin, and marcher spacing, then press **Create form**. A block creates three independently selectable rows.
3. Choose the form in **Selected standing form**, or select one of its marchers.
4. Enter movement, clockwise rotation, or scale and press **Apply group transform**. To change spacing while retaining marcher count and instruments, use **Apply spacing to selected form**.
5. Use **Align X** to make a line along Z, or **Align Z** to make a line along X. **Distribute X/Z evenly** preserves the outermost coordinates on that axis and spaces the other marchers between them.
6. Enable grid snapping and choose a preset, or enter separate **X/Z rounding** intervals. Hold **Shift** to bypass grid and angle snapping temporarily. Use **Round to whole yards**, or press **1** outside input fields, to round the selected form explicitly.

**Lock X/Z translation** prevents movement on that axis during group translation and standing-form controller move/control-point edits. Rotation, scaling, alignment, individual marcher grabs, and route edits are not constrained by these locks.

Every group edit checks body and instrument collisions before applying changes. Rejected edits leave the entire form unchanged. Imported or attached marching routes are not edited by these standing-form controls. Use the separate selection and set editor below for arbitrary selections and explicit authored-set changes. Successful form edits clear erase undo/redo history.

### Create synchronized routes from a destination guide

Select a standing form in **Drill form editor**, close Settings, and draw or stamp a destination guide with the field drawing tools. Choose **Route selected form** in the drawing tray. Marchers are paired with evenly spaced points along the guide in formation order, and a shared count-by-count route planner adjusts paths to avoid collisions while preserving common timing. Playback seeks to count zero and starts after the routes are created. The guide remains editable; individual route counts can be adjusted with the selected marcher's step handles. Route planning replaces the selected form's standing state for playback and does not modify other forms or imported drill sets.

## Select marchers, build shapes, and edit sets

Open **Settings -> Selection, shapes, and sets** and enable **multi-marcher editing**. Playback pauses and marcher POV exits. Close Settings to use the desktop field gestures:

| Gesture | Action |
| --- | --- |
| Click a marcher | Select that marcher, or its grouped shape. |
| Ctrl/Cmd-click | Add or remove one marcher from the selection. |
| Drag empty field space | Rectangle selection; Ctrl/Cmd-drag adds to the selection. |
| Shift-drag | Lasso selection, including loops ending at their starting point. |
| Ctrl/Cmd+A | Select all eligible marchers; text inputs retain native select-all. |
| Drag a selected marcher | Translate the selection. |
| Drag the orange handle | Rotate the selection about its center. |
| Drag a green corner handle | Uniformly scale the selection. |
| Escape | Cancel the current gesture and clear selection; accepted edits are not undone. |

Cyan circles mark selected marchers. Standing mode excludes marchers with routes. **Select current standing form** brings an existing form into the selection. Selection actions use the shared translation, rotation, scale, axis-lock, and grid-rounding settings in the form editor. Alignment and distribution also work on arbitrary selections. **Cycle X/Z rounding** advances the common presets; right-click cycles backward. Hold Shift to bypass configured snapping; the explicit whole-yard rounding action always rounds.

### Custom shapes and grouping

1. Select existing marchers in assignment order, then use **Create line from selected marchers**, or enter a start coordinate and press **Start / reset shape**.
2. Append **Line**, **Single curve** (one quadratic control), **Double curve** (two cubic controls), **Move** (start a disconnected section), or **Close** (connect back to the first point).
3. Use the blue field handles to adjust endpoints and curve controls. **Delete last segment** removes only the most recently appended segment.
4. Press **Apply shape coordinates** to distribute the selected marchers along the drawable length, skipping disconnected gaps, or **Group selection into shape** to retain an editable group. Closed shapes do not duplicate the first marcher.
5. Click a grouped member to select the whole group. Group transforms preserve the guide, and dragging its blue handles reapplies the shape. **Ungroup** removes grouping without deleting marchers or their routes.

These operations reuse marcher identities and instruments; they do not create replacement performers. Grouping standing members detaches them from their previous standing-form guides. Editing only part of a selection shape dissolves that grouping rather than retaining an incorrect guide.

### Explicit authored-set editing

Enable **Edit authored drill sets**, choose a **Destination set**, then select scheduled marchers. Imported page names/counts are retained in the set list; generated drills use eight-count boundaries and their final count.

- Selection transforms, alignment, and shapes edit that set only, rebuilding the selected marchers' transitions linearly to its previous and next set positions. Intermediate midsets in those two transitions are replaced; other marchers and distant counts remain unchanged.
- **Copy positions from previous/next set** reads an adjacent set into the selected destination.
- **Copy grouped shape to previous/next set** applies the current grouped shape to an adjacent destination while retaining the same marcher assignments. Select every member of the source group first.
- Destination body/instrument collision checks are atomic. Intermediate travel is not guaranteed collision-free or physically marchable; inspect playback collision markers and stride warnings afterward.

Resuming playback or seeking away from the edit set disables multi-marcher editing. Enabling placement or erase also disables it. Desktop selection gestures are not headset controller/lasso gestures; the existing XR interaction tools remain available outside this mode.

Edits and shape groups are session-local and reset when the show is replaced or the page reloads. There is no transform/set-edit undo, form persistence, or user-facing `.dots` export. Successful edits clear erase history. Keep your original OpenMarch file for full-fidelity editing and saving.

Implementation: [selection editor](src/interaction/selectionEditor.ts), [shape geometry](src/interaction/drillShapes.ts), and [focused selection-geometry/set transaction checks](scripts/check-drill-shapes.mjs).

### Field chart mode

1. Load an OpenMarch show or generate a drill.
2. Open **Settings -> Selection, shapes, and sets**.
3. Choose a **Destination set** after the opening set and enable **Field chart mode**.
4. Close Settings to inspect the field. Choose another destination set to compare a different transition.

Neither **Enable multi-marcher editing** nor **Edit authored drill sets** is required just to view the chart.

| Chart element | Meaning |
| --- | --- |
| Cyan translucent marchers | Previous set's positions and scheduled facings, using a captured body pose. |
| Real marchers | Selected destination set; playback is paused at that count. |
| Gold arrows | Direction from each old position to its new position. Holds retain their ghost without an arrow. |

Arrows show straight-line displacement, not the route traveled between sets or a collision-free path. Ghosts and arrows are non-pickable, so they do not intercept marcher selection.

Changing the destination set updates the comparison and pauses at the new destination. Editing either endpoint refreshes the chart. The first set has no previous-set comparison; choose a later set to see ghosts and arrows. Marchers without counts in both sets are skipped with a status message. The overlay follows the field in desktop, VR, and rotated/scaled tabletop AR; it does not change the viewing camera to overhead.

Entering chart mode exits marcher POV and ghost-band timeline preview. Resuming playback, seeking away, entering timeline ghost preview, or starting floor calibration turns chart mode off. Turning the toggle off removes the overlay but leaves the real band paused at its current count. Chart mode does not edit schedules, add undo entries, or save itself into drafting camera snapshots. Focused check: `node scripts/check-field-chart-mode.mjs`.

This field overlay is separate from the **Chart** pad (a floating chart page) and **Ghost-band timeline comparison** (a movable timeline preview). It is session-only and off after reload. Implementation: [field chart mode](src/robot/fieldChartMode.ts).

### Selected-marcher footprints

Enable **Show selected marcher's full-route footprints** in Settings, then select a marcher on the field. Cyan left and gold right prints show the gait's actual sole contact anchors at stance entry, sampled through the same leg solver as playback, including bounded stride placement and heel/toe roll compensation. Half-/double-time cadence, MIDI beat units and the current music/drill clock offset, scheduled facing, sideways/backward travel, and forced mark-time gaits determine placement. Initial planted feet are included; repeated mark-time contacts overlap. Prints are projected onto the turf and use a stylized shoe outline; they are not a heel/toe pressure map or recorded playback trail. A halted schedule with no animated interval has no gait contacts to display.

Changing selection, gait, timing, repeat settings, or the route refreshes the overlay; deselection, disabled/deleted marchers, or a marcher without a scheduled route clears it with a status message. The preview samples one pass through the route using current timing/repeat settings, not every possible repetition. Sampling uses isolated gait caches and does not seek or move the real marcher. Footprints are non-pickable, follow tabletop field transforms, and temporarily hide during floor calibration. The toggle defaults off, is session-only, and does not alter playback, drill data, or drafting snapshots. Implementation: [marcher footprints](src/robot/marcherFootprints.ts) and [contact timing](src/robot/marcherFootContacts.ts). Focused checks: `node scripts/check-marcher-footprints.mjs` and `node scripts/check-midi-footfall-position.mjs`.

### Color guard

Choose **Color guard flag**, **Color guard rifle**, or **Color guard sabre** in Settings, the grabbable **Create marchers** panel, or the palm instrument picker. Place performers and give them routes, formations, facings, chart comparisons, and footprints using the same tools as other marchers. Changing equipment for a selected performer preserves their identity and route.

The flag is a static purple/gold silk on a silver pole; the rifle is a solid white parade prop; the sabre is a silver presentation prop. Equipment stays in a fixed hand-held presentation pose during locomotion and carry/play changes. Spins, tosses, cloth physics, and separate guard choreography are not implemented. OpenMarch section names containing `sabre`/`saber`, `rifle`, or `color guard`/`colour guard`/`guard`/`flag` select the corresponding equipment, with specific prop names taking precedence over generic guard names. Existing generated demo sections remain instrumental. Implementation: [guard models](src/robot/colorGuardModels.ts).

### Uniform paint palette

Open **Uniform paint palette** in Settings or **Paint** on the palm menu. The grabbable, kidney-shaped wooden board has real thickness, beveled edges, a through thumb hole, and procedural wood grain. Ten raised, irregular oil-paint blobs have sculpted ridges and glossy lighting, alongside **Paint selected** and **Done paint** controls.

- Choose a swatch, then click a marcher on desktop, trigger a marcher with an XR controller ray, or pinch a nearby marcher with tracked hands. Only that individual's uniform is recolored; their instrument or guard equipment stays unchanged.
- Settings also provides a custom color picker, **Paint individual marcher uniforms** toggle, and **Paint selected marcher** button.
- The marcher's matching route and top-down marker colors update too. Colors survive normal playback and held-marcher rendering changes; other marchers keep their colors.
- Painting takes precedence over selection, route scrubbing, marcher movement, and field-click hiding. **Done paint**, disabling the checkbox, or entering placement, erase, drafting, multi-selection editing, naming, or floor calibration exits paint mode. You can grab/move the palette without painting.
- Paint colors are session-only: there is no paint undo, show export, or inclusion in drafting workspace/camera saves. Reloading or replacing the show creates new default-colored marchers.

Implementation: [marcher paint](src/interaction/marcherPaint.ts). Focused check: `node scripts/check-marcher-paint.mjs`.

### Image projector for tracing

1. In Settings, use **Image projector: local tracing image** to upload a PNG, JPEG, or WebP (up to 16 MB). Nothing is uploaded to a server. Load the image before entering immersive XR.
2. The image is fitted onto the field, preserving aspect ratio. Adjust **Projection center X/Z**, **width**, **rotation**, and **opacity**, or press **Fit image to field**. Zero rotation puts the image's top toward field +Z; transparent image regions remain transparent. Oversized images are downscaled to the device's texture limit, at most 4096 pixels per side, without changing the source file.
3. Pick up a pencil/ruler, yarn, spline, or another existing drawing implement and trace the projected outline. The image is non-pickable and clipped to the field, so it does not intercept field strokes or editable pins. Use **Create formation** or **Create path** on the guide as usual; there is no automatic image-to-route conversion.
4. **Open grabbable image projector** or **Project** on the palm menu summons a physical projector with move, width, turn, fade, fit, and on/off buttons, usable with mouse, controller rays, or hand pinches. Moving/grabbing the device only repositions its controls; its buttons align the image in field coordinates. **Put away** hides the device without turning off the projection.

The projection follows tabletop translation, rotation, and scale. Floor calibration temporarily hides it and blocks alignment. **Remove tracing image** releases the image, including any pending upload, without deleting traced guides or converted performers/routes. Reloading clears the projection. Images and alignment settings are session-only and are excluded from local drafting workspaces and camera photos; save traced guides using the existing drafting controls. Failed/canceled replacements preserve the previous image. Implementation: [projector](src/interaction/fieldImageProjector.ts) and [clipped image geometry](src/interaction/fieldImageProjectionGeometry.ts). Focused check: `node scripts/check-field-image-projector.mjs`.

## Features

- Settings -> **Drill form editor** exposes line, arc, circle, block, polygon, and star tools for standing formations. Choose an empty origin and target spacing to add forms without replacing an imported show. Select a form in the list or select one of its marchers, then translate, rotate, scale, or adjust spacing for the whole form. Spacing changes scale the form while preserving its marcher count, identities, and instruments; original curve sampling may round intervals to fit endpoints.
- Optional field-grid snap uses 0.3125, 0.625, 1.25, 2.5, or 5-yard intervals; angle snap uses 45 degrees. Settings and the XR palm form library share snap/spacing settings. The palm library also provides spacing, rotation, and scale buttons; existing controller/hand handles still move and reshape forms. Group edits validate all marchers together and roll back on collisions. Imported marching routes are intentionally excluded from these standing-form controls. Run `node scripts/check-drill-editing.mjs` for focused checks.
- **Show adjustable grid on field** displays a separate, non-snapping turf overlay. Set its spacing from 0.5 to 20 yards; it is independent of the editor's snapping intervals.
- Run `node scripts/check-adjustable-grid.mjs` to check grid visibility, spacing changes, field alignment, and invalid input handling.
- Each block row is a separate selectable form. The original form controls edit one standing form at a time; the selection editor supports arbitrary multi-selection. Neither editor adds form saving/export or transform undo/redo; successful edits clear existing erase history.
- OpenMarch-style alignment tools in the same editor align X or Z to the form's average coordinate, distribute marchers evenly between the existing axis extremes, or round positions to whole yards (keyboard `1` outside text fields). Marcher order, identity, height, facing, and instruments are preserved; collisions reject the entire operation, and imported/attached routes remain protected. Alignment replaces the form's guide with a connected guide through the edited marcher positions rather than fitting it back to a circle.
- Grid presets populate independently editable X/Z rounding intervals (0.001–10 yards). Hold `Shift` to bypass grid and angle snapping temporarily; releasing Shift or leaving the window restores the configured settings. X/Z translation locks apply to the form transform and standing-form controller move/control-point handles, including when snapping is enabled. They do not constrain rotation, scaling, alignment, individual marcher grabs, or marching-route edits.

- Palm-menu instrument buttons display miniature 3D instrument models instead of abbreviations. Their existing click/trigger/pinch targets and active-instrument highlight are preserved.
- **Field drawing tools:** open **Tools** on the palm menu or **Open field drawing tools** in Settings. A felt-lined, metal-rimmed tray holds actual 3D implements, not selection tiles: a hexagonal yellow pencil with wood/graphite tip, ferrule and rubber end; a sleeved eraser; a translucent straightedge with graduations; a semicircular protractor with markings; and a hinged compass with needle and pencil legs. Grip/pinch the implement itself to lift it out of the tray without a pose jump. Multiple implements may be out at once and stay where released. While held, touch the tip/edge to the field: pencil records freehand strokes, ruler lays a straight edge, protractor lays a semicircular arc, and compass lays a full circle about its pivot. Pencil contact close to a laid-down ruler's edge snaps onto that edge. The live preview is cyan; completed layout guides appear as red yarn, held down by red-headed thumbtacks at intervals and sharp corners. **Span -/+** scales the selected implement from 50% to 300%; contact uses world-space tolerance and transforms geometry into field coordinates, including rotated/scaled tabletop AR. These are drawing/stamping aids, not a rigid-body physics simulation; the protractor/compass generate their complete arc/circle on contact rather than requiring a traced sweep.
- **Stencil tray:** open **Sten** on the palm menu or **Open stencil tray** in Settings. Circle, square, triangle, pentagon, hexagon, and star stencils are physical flat frames with open centers, arranged on the tray with noninteractive name labels. Grab a frame, press it flat against the field, and lift to leave a guide. **Cookie cutter tray** (**Cut** on the palm menu, or **Open cookie cutter tray** in Settings) holds the same six shapes as physical metal cutters with raised walls and rolled rims: pressing/lifting stamps a standing formation directly, using the current instrument and formation spacing. A blocked stamp is rejected with a notice instead of overlapping marchers; increase formation spacing in Settings if the current instrument does not fit.
- **Laser level:** grab the black laser with the green lens from the Tools tray. Its horizontal orientation projects a bright green line across the field, clipped to the field boundaries, without requiring turf contact. It projects in both directions like a drafting alignment line; this is not a physical light or ray-tracing simulation. Moving or rotating the held laser updates the line, and releasing it turns the beam off. Aim it approximately parallel to the field; a nearly vertical aim or a line that misses the field has no projection. With the other hand/controller, choose **Pin laser line** on the Tools tray to save the current line as a yarn-and-thumbtack guide. On desktop, pick up the laser and drag on the field to set its position and direction; the live preview remains after mouse release so you can click **Pin laser line**. Drag again to re-aim, or use **Put away** to turn it off. Pinning is explicit: aiming and releasing never create a guide automatically. Pinned lines support the existing **Create formation**, **Create path**, eraser, **Undo guide**, and **Clear guides** actions. Projection follows rotated/scaled tabletop fields, and floor calibration blocks laser use. Laser guides remain session-local until reload.
- **Advanced drafting tray:** choose **Advanced tools** on the Tools tray or **Open advanced drafting tools** in Settings. The tray holds nine physical, grabbable implements, including a sticky-note pad. Pick one up with the mouse, controller grip, or hand pinch. On desktop, drag on the field after selecting an implement. In XR, hold it with the working edge flat against the field, then lift or release to finish. The tray status displays spacing, set-square angle, offset side, and T-square reference mode; its controls also let you convert, undo, clear, save locally, restore, or put away tools. Settings provides precise numeric spacing and note text.

  | Tool | Behavior |
  | --- | --- |
  | T-square / parallel ruler | Constrains a line to the nearest field X/Z axis. **Parallel ref** switches to the newest guide's start-to-end direction, allowing parallel lines at another location. Closed guides cannot supply that direction. |
  | Set square | Constrains the line to multiples of 30, 45, 60, or 90 degrees relative to field X. Use **Angle** to cycle, or choose the angle in Settings. |
  | Dividers | Adds a copy of the newest guide with equally spaced tack marks measured along its path; without an existing guide, uses the drawn segment. **Spacing -/+** or Settings sets 0.05-20 yards. A final short remainder is not marked as a full interval. At most 512 intervals are allowed. |
  | Measuring tape | Saves a dimension line labeled in yards, 8-to-5 marching steps, and heading in degrees from field +X toward +Z. Drag the endpoint pins to remeasure; the label updates. |
  | French curve / spline | Creates a smooth quadratic curve with two endpoint pins and one bend-control pin. Drag any of the three to reshape the saved guide. This is an editable three-control spline, not a library of fixed French-curve templates. |
  | Parallel offset | Copies the newest guide at the configured spacing. **Offset side** switches left/right along its point order. Straight segments offset exactly; corners use miter joins limited to four times the offset. Out-of-field results are rejected rather than clipped. Complex/self-intersecting offsets are not repaired automatically. |
  | Annotation pen | Places the text from **Annotation text** in Settings beside a leader line. Text is limited to 80 characters; empty notes are rejected. |
  | Sticky-note pad | Click the field (or touch/lift the held pad) to place a yellow note using **Annotation text** from Settings. Text wraps across the note. Drag either red pin to move the entire note without stretching it. Eraser, Undo guide, and Clear guides remove notes like other guides; local save/restore includes their text and positions. |
  | Yarn and thumbtacks | Places a yarn line between two independently movable red pins. **Add tack** inserts a pin at the longest span's midpoint; drag it to the desired field location to create another segment. Up to 64 pins per line. The same action can subdivide a tape measurement into a measured polyline. |

  Editable pins can be mouse-dragged on the field or gripped/pinched in XR. Their field-local positions drive the guide geometry used by **Create formation/path**, not just the display. Pins remain on the turf, and out-of-field or collapsed adjacent-pin moves are rejected. Pins have a minimum tabletop visual size to remain usable while the stadium is shrunk. Ordinary drawing tools still create decorative tacks; yarn, tape, spline, and sticky notes create editable pins. Editing a source guide does not automatically change previous offsets, divider copies, or already converted marchers/routes. Undo removes a whole guide, not individual pin moves. Unsaved drafting is cleared by reload; use the local workspace controls below to preserve it. Drafting is not exported to OpenMarch. Floor calibration blocks drawing and pin editing. Run `node scripts/check-field-drawing-tools.mjs` for the focused geometry, interaction, persistence, and cleanup checks.
- **Local drafting workspace:** choose **Save drafting locally** in Settings or **Save locally** on the advanced tray. One snapshot per browser/site address stores committed guides, yarn/spline controls, divider marks, notes, measurements, drafting spacing/angle/text/reference settings, and visible-grid spacing/visibility. Save again to overwrite it after changes; this is not autosave. **Restore saved drafting** rebuilds editable guides and settings without changing marchers, routes, or the show. When current guides exist, press Restore twice within ten seconds to confirm replacement. Invalid or unsupported saved data leaves current guides intact, and storage failures are reported. **Delete saved drafting** removes only the stored snapshot; current guides remain. Saves use browser local storage, are not uploaded, and do not transfer across devices, browsers, ports, or site addresses. Clearing site data deletes the save. Live strokes, unpinned laser previews, wire bends, tool/tray poses, editor snap settings, and marching content are excluded. There is no automatic restore on startup. Older descriptions of session-local guides mean unsaved guides; committed laser and drawing guides can be included in this snapshot.

Press the shutter with your other hand, use **Take photo** on the advanced tray, or **Camera: take field snapshot** in Settings. It captures a clean overhead PNG of the field, committed drafting, and visible grid, not the desktop UI, marchers, routes, or live beams. Framing follows tabletop transforms rather than the camera's handheld aim. One photo and its restorable drafting workspace are stored together locally, separately from the regular drafting save. Settings shows the saved thumbnail, including after reload. **Restore photo** on the tray or **Restore camera snapshot** in Settings restores the paired guides/settings; press twice within ten seconds when current guides exist. It never restores marchers or routes. **Download PNG / Download field photo** exports just the image, not a portable workspace backup. Release other tools and pins before capture; holding the camera is allowed. Edits are blocked during capture, and changing settings during capture rejects the save rather than pairing an image with different drafting. Capture, corruption, and browser quota errors preserve the previous saved photo and report a notice. Clearing site data removes both local saves; nothing is uploaded. **Delete saved drafting** removes only the stored snapshot; current guides remain. Saves use browser local storage, are not uploaded, and do not transfer across devices, browsers, ports, or site addresses. Clearing site data deletes the save. Live strokes, unpinned laser previews, wire bends, tool/tray poses, editor snap settings, and marching content are excluded. There is no automatic restore on startup. Older descriptions of session-local guides mean unsaved guides; committed laser and drawing guides can be included in this snapshot.
- **Desktop drawing:** pick up a physical tool/stencil/cutter from its tray with the mouse, then drag on the field. Mouse camera rotation is suspended during the stroke and restored on release; losing window focus cancels the unfinished stroke. Pencil follows the stroke; ruler uses drag endpoints; protractor, compass, stencils, and cutters use the drag start as center and the endpoint as radius/orientation. Circle/polygon guides remain closed. **Create formation** and **Create path** convert the newest guide into a standing form or a new marcher's route. - Marchers are robots with a low-poly humanoid android head in the same smooth-shaded style as the body: a pale rounded skull with a flat face, a navy visor band with glowing cyan eyes, a mouth slit, and disc ears, under the shako and plume.
- Marcher bodies are simplified for Meta Quest: every part comes from a shared low-poly, vertex-colored template. The pelvis, neck, head, shako, and plume are merged into one mesh, and each arm segment includes its own joint ball. A marcher (with its trumpet) is 17 meshes, down from 26. Every part is drawn with hardware instancing: each template has one hidden instance source and the team color is a per-instance color, so the whole band renders in a few dozen draw calls. Top-down video-board markers are instanced too. While a marcher is held or previewed, its parts temporarily become ordinary clones so they can render on top in a separate rendering group. They switch back to instances when released.
- Static stadium geometry is kept light. Stand risers, benches, and walls, as well as goal-post parts, are merged into one mesh per material. The field is a single quad, the video-board hash marks are flat quads, and path tubes are simplified (Ramer–Douglas–Peucker) before tessellation. Without the marchers, the static scene dropped from about 78,000 to 16,000 vertices. Draw calls fell from 87 to 61.
- In Giant and tabletop modes (any time the field is shrunk below full scale) marchers and instruments switch to reduced-detail versions of the same templates: instruments retain round 6–24-sided tubes, caps, and drum shells with two thirds of the full-detail radial tessellation, body lathes have half the sides, the head is a smooth four-sided skull with its visor, and small details (valve buttons, keys, ligature, mouth, ears) are skipped. Existing marchers swap geometry in place when the scale changes, and new marchers and instrument changes use the current level.
- Instruments use smooth-shaded circular cross-sections at full scale: 9–18 sides for tubing, 24–36 for bell rims and larger drum shells, with matching tessellation for caps and bell transitions. Full-detail instrument templates total 8,034 vertices instead of 10,600 (24.2% fewer), without reducing bend subdivisions, body/face/joint detail, or the existing reduced-detail instruments. The sousaphone body loop has 32 segments at full scale and 16 when shrunk. Mouthpiece and grip positions, colors, and playing/carry poses are preserved; template bounding-box corners change by less than 0.003 model units. Hardware instances and held-marcher clones still share their template geometry, with no extra meshes or materials. Validate both detail levels with `node scripts/check-instrument-geometry.mjs`.
- Instrument tubing bends are rounded with quadratic fillets rather than sharp corners. A 90-degree bend has eight curved segments at full scale and four when shrunk; tighter turns get more segments. Fillets stay within 30% of the shorter neighboring segment, preserve open tube endpoints, interpolate bore radii, and leave straight sections and marcher bodies unchanged.
- Instrument tubes are seam-free: bends are mitered so they never pinch, each bell flares straight on from its pipe as one tube, mouthpieces sit inside straight receivers, tube ends finish inside valve blocks and braces, and the sousaphone's body loop is closed. Marcher joints are seamless too: shoulders, elbows, hips, and knees bend around rounded caps, and the forearm stretches slightly when a grip is just out of reach, so wrists stay attached to the hands.
- Marchers hold their instrument with both glove hands in playing and carry poses, with articulated elbows connecting their sleeves to the instrument's grip points.
- Trumpets are a procedural B♭ horn sized for Meta Quest: mouthpiece, leadpipe and tuning slide, valve block with three pearl buttons, bell bow, and flared bell at true proportions. Every horn is an instance of one shared, hand-indexed 883-vertex mesh with a single vertex-colored material, so all trumpets share one draw call. The left hand wraps the valve casings and the right hand rests on the buttons.
- Mellophones use the same style and right-handed valve layout as the trumpet, with a longer leadpipe, a deeper tuning-slide wrap, and a much larger forward bell, as one shared 811-vertex mesh. They are held like a trumpet when played and carried upright with the bell down.
- Alto saxophones use the same style: a conical body, bow and upturned bell in one rounded tube, a curved neck, a black mouthpiece, and pearl key stacks, as one shared 897-vertex mesh. The left hand sits on the upper key stack and the right hand on the lower; when played, the horn hangs down and slightly out to the marcher's right.
- Baritone saxophones are about one and a half times the alto's size, with a wider bore and bell and an open S-curved neck above the body, not a spiral (1,617 vertices). They are held further out to the marcher's right.
- Euphoniums are carried like the mellophone with a large front-facing bell, wrapped leadpipe, valve block, and three pearl valve buttons (1,099 vertices).
- Trombones use the same style: mouthpiece, a widened forward slide with its crook and brass crosspiece, and a bell section whose tuning slide passes over the marcher's left shoulder. The return rail lines up with the bell section and runs straight into it without sideways neck bends, so the whole horn is one continuous tube, as one shared 692-vertex mesh. The left hand rests beside the receiver and the right hand holds the brass crosspiece at first position. There is no crosspiece attached to the mouthpiece, and both gloves stay clear of the main tubes. In the carry pose the trombone is held upright with the slide pointing down.
- Clarinets use the same style: a black mouthpiece with a silver ligature, barrel, straight body with silver front key clusters, and a flared bell, as one shared 289-vertex mesh. They are played angled about 40° below horizontal, with the left hand on the upper joint and the right hand on the lower joint, and carried upright in front of the chest.
- Flutes use the same style: a silver head joint and body with a lip plate, a dark embouchure hole, and front key rows, as one shared 129-vertex mesh. They are played level out to the marcher's right, with the lip plate under the mouth grille, the foot angled slightly forward, and the left hand crossing in front of the chin with its elbow swung out to the side, clear of the chest. They are carried upright with the crown up.
- Sousaphones are worn rather than held, as one shared 2,164-vertex brass mesh: a tilted body loop rests on the left shoulder and passes under the right arm, a gooseneck reaches the mouth, and the bell faces forward above the shako. The right hand sits on the valves and the left hand on the front of the loop; playing and carrying use the same pose.

- Automatic gait: when the scoreboard gait selector shows `AUTO` (Field March, High Step, Parade, or Knee-Ankle March style), each marcher's gait is worked out count by count from its facing, travel direction, and step size. A stationary count is mark time (high mark time for High Step/Knee-Ankle). Travel within 50° of facing marches forward in the selected style, beyond 130° is a backward march (backward high step for high-lift styles), and in between is a crab walk with legs along the line of travel. Steps shorter than 0.36 yd per count (for example 16-to-5) march half time, and steps longer than 1.05 yd (for example 4-to-5) double time, so the stride stays near 8-to-5. Marchers whose route has ended halt at attention. Selecting any other gait (Crab Walk, Slide, Mark Time, Double Time, Backward March, and so on) forces it on every marcher as before. Full-scale VR keeps your physical eye height when standing, so your real floor stays level with the turf (including any saved floor calibration), and uses a 1.2 m virtual eye height in Sitting mode; Giant and tabletop modes preserve physical eye height. AR headset tracking is unchanged.
- In VR and AR, physical headset height automatically selects sitting or standing table height after one second of stable detection. Initial detection uses 1.425 m; subsequent transitions use below 1.35 m for sitting and at least 1.5 m for standing. Tabletop entry also adjusts height immediately when a tracked pose is available. Automatic detection does not change virtual eye height, is paused during floor calibration, and leaves manual table-height adjustments intact until the next detected posture change.
